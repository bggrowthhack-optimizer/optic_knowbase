# Методика: «Что мешает плану»

## 1. Назначение

Документ описывает, как блок «Что мешает плану» (вкладка «Обзор месяца», окно «Анализ филиала») считает и приоритизирует причины недобора плана. Нужен разработчику как источник логики расчёта.

## 2. Термины

- **Подбор** — фактический приём с диагностикой и подбором очков у врача.
- **Рецепт** — клиент, которому наш врач выписал хотя бы один рецепт (считается по клиентам, не по визитам).
- **Заказ** — клиент оплатил покупку (очки/линзы).
- **Окна** — плановая ёмкость врача (сколько приёмов вмещается в рабочее время). Не управляется консультантом или врачом напрямую, в дерево причин не входит.
- **Трафик → Подбор** — какая доля обратившихся реально дошла до приёма. Не то же самое, что «% загрузки» (Подборы ÷ Окна) — загрузка про использование уже существующей ёмкости врача (не в фокусе), а трафик→подбор про то, доходит ли входящий интерес до приёма вообще (управляется консультантом).
- **Свои клиенты** — прошли диагностику (рецепт) у нас.
- **Чужие рецепты** — клиент пришёл с рецептом не от нас (из другой клиники), покупает у нас без нашей диагностики.
- **ВТЛ** — высокотехнологичные линзы, премиальная категория линз дороже обычных.

## 3. Как считать вклад одной причины в деньгах

Это единственная формула в документе, она используется везде — и чтобы сравнить причины между собой, и чтобы посчитать итоговую сумму в строке причины.

**Правило:** берём вообще все метрики, из которых складывается выручка, как есть по факту — кроме одной, той самой метрики, которую проверяем. Меняем только её на план. Пересчитываем выручку с этим одним изменением. Сравниваем с фактической выручкой — разница и есть вклад причины в рублях.

Важно: сравниваем всегда с одной и той же фактической выручкой филиала целиком, а не с вкладом родительского узла в дереве. Это касается любого шага ниже — даже если мы уже решили, что копаем внутри «Количества», вклад каждой находящейся там причины всё равно считаем от общей выручки филиала, а не как долю от вклада «Количества».

Суммы причин не обязаны точно сходиться с общим недобором (если отклонилось сразу несколько метрик, у них есть небольшой эффект взаимного влияния) — остаток уходит в последнюю строку сверки «Остальные Z ₽».

Плановое значение для каждой метрики (конверсии, доля ВТЛ, целевой чек и т.д.) берём из существующего инструмента разбивки плана продаж — РОП/КД уже вводит эти цифры там, здесь их не вводят заново.

### Пример

Факт воронки: 1000 обратившихся → 70% дошли до подбора → 700 подборов → 90% подбор→рецепт (план 95%) → 630 рецептов → 78% рецепт→заказ → 491 заказ свой. Плюс 50 чужих заказов. Итого заказов факт — 541. Чек факт — 5800 ₽. Выручка факт = 541 × 5800 = 3 137 800 ₽.

Проверяем причину «подбор→рецепт ниже плана»: меняем только эту метрику на план (95%), всё остальное — по факту (1000 обратившихся, 70% дошли до подбора, 78% рецепт→заказ, 50 чужих заказов, чек 5800).

Пересчитываем: 700 подборов × 95% = 665 рецептов. 665 × 78% = 519 заказов своих. 519 + 50 = 569 заказов итого. Выручка = 569 × 5800 = 3 300 200 ₽.

Вклад причины = 3 300 200 − 3 137 800 = **162 400 ₽**.

## 4. Дерево причин — полная структура

У каждого узла — своя формула и список детей (более конкретных причин). Спускаемся по дереву сверху вниз (как идти по нему — в п.5).

**Выручка = Количество заказов × Средний чек заказа.** Точное тождество для факта — это и есть корень дерева, два ребёнка.

### Ветка «Количество заказов»

Количество заказов = заказы по своим клиентам + заказы по чужим рецептам.

- **Заказы по чужим рецептам** — отдельное измеренное число, дальше не раскладывается. Это и есть причина (лист). Отвечает консультант.
- **Заказы по своим** = подборы × % подбор→рецепт × % рецепт→заказ. Количество подборов, в свою очередь, зависит от трафика (если он считается): подборы = обратившиеся × % трафик→подбор. Раскладывается на три причины, дальше не делится ни одна из них (все — листья):
  - **Трафик → Подбор** (% обратившихся, дошедших до приёма) — отвечает консультант.
  - **Подбор → Рецепт** (% приёмов, закончившихся рецептом) — отвечает врач.
  - **Рецепт → Заказ** (% рецептов, закончившихся покупкой у нас) — отвечают врач и консультант вместе (см. п.7 про двойной эффект врача).

Если трафик не считается в проекте — шаг «Трафик → Подбор» просто не используется, воронка своих начинается сразу с подборов.

### Ветка «Средний чек заказа»

Средний чек = чек по линзам + чек по оправе (чек работы мастера в причины не включаем — он почти не меняется).

- **Чек по оправе** — отдельное измеренное число, дальше не раскладывается. Лист. Отвечает консультант.
- **Чек по линзам** — складывается из чека своих клиентов и чека чужих клиентов, взвешенных по доле каждой группы в заказах. Раскладывается на три причины:
  - **Чек линз у своих ниже плана** (доля своих/чужих и чек чужих держим по факту, меняем только чек линз своих) — отвечают консультант и врач.
  - **Чек линз у чужих ниже плана** (аналогично, меняем только чек линз чужих) — отвечает консультант.
  - **Доля чужих заказов сдвинулась от плана** (чек своих и чек чужих держим по факту, меняем только долю чужих в общем количестве) — отвечает консультант. Это не то же самое, что «Заказы по чужим рецептам» в ветке количества: там считаем причину нехватки количества заказов, здесь — причину того, что из-за другого состава заказов просел именно чек.

  **Пример.** Факт: доля своих заказов — 85%, доля чужих — 15%. Чек линз своих факт 4200 ₽ (план 4500 ₽). Чек линз чужих факт 3000 ₽. Доля чужих по плану — 12%. Общее число заказов факт — 541.

  Текущий чек линз (факт) = 0,85 × 4200 + 0,15 × 3000 = 4020 ₽.

  Вклад причины «чек линз у своих ниже плана»: меняем только чек своих на план (4500 ₽), долю и чек чужих держим по факту → 0,85 × 4500 + 0,15 × 3000 = 4275 ₽. Разница с фактом — 255 ₽ на заказ, на 541 заказов это 255 × 541 = **137 955 ₽**.

  Вклад причины «доля чужих сдвинулась от плана»: меняем только долю на план (12% чужих вместо 15%), чек своих и чек чужих держим по факту → 0,88 × 4200 + 0,12 × 3000 = 4056 ₽. Разница с фактом — 36 ₽ на заказ, на 541 заказов это 36 × 541 = **19 476 ₽**.

  Если «Чек линз у своих» сам по себе проседает — раскладываем ещё на один уровень глубже, на долю ВТЛ:
  - **% продаж ВТЛ среди своих** — отвечают врач и консультант.
  - **Ср.чек именно ВТЛ-линз среди своих** — отвечают врач и консультант.
  - **% рекомендаций ВТЛ** — отвечает врач. Отдельно от своих/чужих не делится — рекомендация возможна только для своих клиентов (чужим рецепт выписывают не у нас).

  Если «Чек линз у чужих» сам по себе проседает — раскладываем так же, но без рекомендаций (у чужих клиентов рекомендации врача не было):
  - **% продаж ВТЛ среди чужих** — отвечает консультант.
  - **Ср.чек именно ВТЛ-линз среди чужих** — отвечает консультант.

Все показатели, помеченные как «отвечает…» без дальнейшего пояснения — это листья дерева, глубже не раскладываются.

## 5. Как идём по дереву

1. Берём текущий узел (стартуем с корня — Количество / Чек).
2. Считаем вклад каждого ребёнка в деньгах (по формуле из п.3 — каждый раз от общей факт-выручки филиала, не от вклада родителя).
3. Сортируем детей по убыванию вклада. Берём по убыванию, пока сумма не наберёт примерно 80% от вклада родителя — это «значимые» дети. Остальные дальше не трогаем, их вклад остаётся в «Остальные ₽».
4. Для каждого значимого ребёнка: если у него есть свои дети (он не лист) — заходим внутрь и повторяем шаги 1–3 уже для него. Если это лист — он становится финальной причиной в списке.
5. Когда во всех ветках дошли до листьев — это и есть итоговый список причин для показа (до применения правила «объединять/разделять», см. п.6).

**Отрицательный вклад.** Если у ребёнка вклад отрицательный (эта метрика не хуже плана, а лучше — тянет результат вверх) — он не причина, в сравнение и в сумму на 80% не берём, как будто его вклад равен нулю.

**Если 80% не набирается.** Если сумма вкладов всех детей с положительным вкладом всё равно меньше 80% от вклада родителя (разницу съедает остаток от взаимного влияния метрик) — берём всех детей с положительным вкладом, больше брать нечего, на этом останавливаемся.

**Если один ребёнок уже больше 80%.** Берём только его — правило «пока не наберём 80%» выполняется уже на первом ребёнке, в остальных не копаем.

**Пример.** Общий чек просел → считаем вклад чека своих, чека чужих, сдвига доли, чека по оправе → значимы, допустим, только чек своих и сдвиг доли → в чек своих заходим глубже: он сам раскладывается на долю ВТЛ → значим только % продаж ВТЛ среди своих → это лист, финальная причина. Сдвиг доли — тоже лист, вторая финальная причина. Чек чужих и чек по оправе дальше не трогаем, их вклад ушёл в «Остальные ₽».

## 6. Объединять или разделять похожие причины

Среди причин, отобранных по п.5: если у двух причин одинаковый по сути способ исправления (один и тот же человек должен сделать примерно одно и то же) и близкий вклад в рублях — объединяем в одну строку с суммарным вкладом. Если способ исправления разный — показываем раздельно, даже при разном вкладе.

## 7. Особый случай: трафик

Нет данных по трафику в проекте — шаг «Трафик → Подбор» просто не используется (см. п.4). Есть данные, но ставить на этом фокус не стоит (это легко превращается в оправдание бездействия для сотрудников) — если трафик всё же попал в причины, его всегда ставим последней строкой списка, с суммой как остаток от общего недобора, а не по расчёту из п.3. Конкретное действие (обзвон базы, рассылка, приглашение родственников, купоны) выбирается по ситуации, не фиксированным текстом.

## 8. Особый случай: двойной эффект врача

Нехватка рекомендаций ВТЛ врачом может быть причиной сразу в двух местах дерева одновременно: и в низких продажах ВТЛ (ветка чека), и в низкой конверсии рецепт→заказ (ветка количества — клиент меньше доверяет без убедительной рекомендации). Деньги по каждой причине считаем отдельно (это два разных места недобора), но если в итоговом списке оказались обе и обе указывают на врача — в тексте объединяем в одну формулировку, не пишем про врача дважды. Это не отдельная проверка в коде — объединение делает тот же LLM-шаг генерации текста (п.9): ему передаётся весь отобранный список причин целиком, и он сам видит, что две причины из разных мест дерева — по сути про одного и того же человека.

## 9. Откуда берётся текст причины

Формулировку («крупно — что исправлять») генерирует LLM — подбирает и адаптирует текст под конкретную ситуацию, не вставляет готовый шаблон. Ниже — базовый список типовых причин по показателям и ролям, на который LLM опирается.

| Показатель | Сотрудник | Типовые причины |
|---|---|---|
| Трафик → Подбор | Консультант | Не встречает клиента дружелюбно и профессионально; не выясняет потребность и причину визита; не объясняет важность диагностики зрения; не мотивирует на приём к врачу |
| Подбор → Рецепт | Врач | Не проводит полную диагностику; не выявляет все показания для коррекции; не выписывает рецепт при наличии показаний |
| Рецепт → Заказ | Врач | Не выясняет реальные жалобы клиента; не связывает проблемы с жалобами; объясняет диагноз медицинскими терминами; не рассказывает, как очки решат проблему; не объясняет последствия отказа; плохо передаёт информацию консультанту |
| Рецепт → Заказ | Консультант | Не выясняет у врача рекомендации; не объясняет рекомендации простыми словами; не работает с возражениями; не работает с ушедшими клиентами |
| Заказы по чужим рецептам | Консультант | Не работает с клиентами, которые пришли с чужим рецептом, как с потенциальной продажей; не предлагает пройти диагностику у нас; не удерживает клиента ценой/сервисом при сравнении с другими точками |
| Чек по оправе | Консультант | Не выясняет образ жизни и стиль; не использует техники продаж оправ; не работает с возражениями по цене |
| Чек линз у своих / у чужих | Консультант | Не предлагает более дорогие варианты покрытий/категорий; не выясняет потребности клиента; не использует техники продаж |
| Чек линз у своих | Врач | Не объясняет разницу между категориями обычных линз (покрытия и т.п.); решает за клиента, что ему дорого |
| Доля чужих заказов (сдвиг) | Консультант | Не предлагает клиентам с чужим рецептом пройти диагностику у нас; не объясняет разницу в сервисе и гарантии между нашей диагностикой и внешним рецептом |
| % рекомендаций ВТЛ | Врач | Не знает показания для ВТЛ; боится ошибиться в подборе; решает за клиента, что ему дорого |
| % продаж ВТЛ среди своих / ср.чек ВТЛ среди своих | Врач | Не объясняет разницу между простыми и ВТЛ; плохо передаёт информацию консультанту; не выясняет сложные зрительные задачи; не знает различия между категориями ВТЛ |
| % продаж ВТЛ среди своих / ср.чек ВТЛ среди своих | Консультант | Не знает ассортимент и линейку ВТЛ по ценам; не выясняет рекомендации врача; не объясняет пользу ВТЛ; не выясняет дополнительные потребности; не предлагает и не презентует покрытия; не использует техники продаж; не знает скрипты работы с возражениями |
| % продаж ВТЛ среди чужих | Консультант | Не предлагает ВТЛ клиентам с чужим рецептом вообще; не умеет обосновать пользу ВТЛ без опоры на рекомендацию врача (её нет); не выясняет потребности клиента для обоснованного предложения |
| Ср.чек ВТЛ среди чужих | Консультант | Сразу предлагает самый дешёвый вариант ВТЛ, не выясняя потребности; не презентует более дорогие категории и покрытия чужим клиентам |
